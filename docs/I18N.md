# Internacionalização (next-intl v4)

| Item | Valor |
| --- | --- |
| Locales | `pt-BR` (padrão) e `es-PY` |
| Prefixo | `localePrefix: "as-needed"` → `/produto/x` (pt-BR) e `/es-PY/produto/x` (es-PY) |
| Detecção automática | desligada (`localeDetection: false`) — o usuário troca na Conta |
| Fuso | `America/Sao_Paulo` |
| Roteamento | `src/proxy.ts` (Next 16 chama o middleware de *proxy*) com `createMiddleware(routing)`; matcher ignora `/api`, `/_next`, arquivos com extensão e os service workers |

## Arquivos

| Arquivo | Função |
| --- | --- |
| `src/i18n/routing.ts` | `defineRouting` (locales, default, prefixo) + tipo `AppLocale` |
| `src/i18n/navigation.ts` | `Link`, `useRouter`, `usePathname`, `redirect`, `getPathname` cientes de locale — **use sempre estes**, nunca `next/link` para rotas internas |
| `src/i18n/request.ts` | `getRequestConfig`: resolve locale, carrega mensagens, define formatos de data (`short`, `long`, `dateTime`) |
| `src/i18n/messages/pt-BR.json` / `es-PY.json` | mensagens por namespace |
| `src/i18n/messages/index.ts` | `loadMessages(locale)` (import dinâmico) |
| `src/global.d.ts` | tipagem forte (`AppConfig.Messages`) — chaves inexistentes viram erro de TypeScript |
| `app/[locale]/layout.tsx` | `generateStaticParams`, `setRequestLocale`, `<NextIntlClientProvider>` |

## Namespaces

`common`, `nav`, `validation`, `errors`, `pwa`, `home`, `catalog`, `product`, `seller`, `cart`, `checkout`,
`payment`, `orders` (inclui `orders.status.<OrderStatus>`, `paymentMethod`, `paymentStatus`), `account`, `auth`,
`sellerPanel`, `admin`.

## Sintaxe (ICU MessageFormat)

```jsonc
"cartWithCount": "Carrinho, {count, plural, =0 {vazio} one {# item} other {# itens}}",
"iosHint": "No Safari, toque em <share></share> Compartilhar…",   // rich text: t.rich("iosHint", { share: () => <Icon/> })
"androidSteps": ["…", "…"]                                          // arrays: t.raw("installPage.androidSteps") as string[]
```

Uso:
```tsx
const t = useTranslations("catalog");          // client ou server component
t("resultsCount", { count: 12 });
const format = useFormatter();                  // format.dateTime(date, "short"), format.number(...)
const tv = useTranslations("validation"); tv(errorMessageKey);   // mensagens Zod são chaves deste namespace
```
No servidor (metadata): `await getTranslations({ locale, namespace: "common" })`.

## Convenções

- Rotas ficam em **português** nos dois idiomas (`/carrinho`, `/conta/pedidos`); só o prefixo muda. Se quiser
  segmentos traduzidos, use `pathnames` em `defineRouting`.
- Mensagens de validação Zod retornam **chaves** (`"invalidCpf"`) e a UI traduz.
- Dinheiro não passa pelo next-intl: usa `formatMoney` (locale natural da moeda), para que BRL apareça sempre como
  `R$ 1.234,56` e PYG como `₲ 1.234.567` independentemente do idioma da UI.
- Novas chaves: adicionar nos **dois** JSONs (o typecheck falha se faltar no pt-BR, que é a fonte do tipo).
- Troca de idioma: `<Link href={pathname} locale="es-PY">` (na página Conta).
